# 请求处理与前端回显规则

## 模型身份与日志

每次模型调用分别保存 `model_identity.configured_model`（配置值）、
`requested_model`（该次实际请求参数）、`response_model`（服务响应声明值）。
`source=response_body` 表示在 SDK 用请求值补齐之前读取了原始响应字段；未返回时为
`unknown`，`response_model` 和步骤的 `model` 为 null，不用配置值冒充。
`sdk_model` 仅作为 SDK 聚合结果保留，不是模型身份的依据。
服务响应声明不能独立证明远端部署权重，`independently_verified` 始终为 false。

主回答、过期推断、修复、重试、画像总结和提醒均使用相同的观测客户端；
网页搜索从其独立 HTTP 响应读取身份。启动本地 Qwen 服务不会自动切换主助手的
`LLM_PROVIDER`。配置和请求名称相同、响应别名不同的情况如实并存，不自动猜测映射。

## 输入与路由

1. 先验证文字和图片限制。图片请求不进入纯文本分类器。
2. 确定性的库存操作、取消和菜谱推荐请求先路由；例如“根据库存推荐一道菜，
   并避开我的过敏原”属于菜谱请求，库存只是检索依据，不会被分类器否决。
   对显式按库存推荐的请求，业务层先读取库存并作为 inventory_snapshot 提供给助手；
   该读取标记为 business_rule，不能伪装成模型发起的工具调用。
3. 分类器仅处理无法确定的文本；不可用时继续交给助手。无关问题按原规则拦截。
4. 低置信度图片候选先由用户校对，未确认的候选不作为确定食材传给助手；中等置信度保留提醒。

## 库存与确认

- 查询逐条返回名称、完整数量原文和易读过期时间；同名条目不合并。
- ID、日期来源枚举和原始时间戳保留在工具记录与日志中。库存卡片的“操作标识”
  可展开获取完整 ID，用于同名条目的精确选择；不使用短前缀执行修改。
- 除新增外，先查询目标再创建变更提案。数量仍是不透明文本，不自动扣减或换算。
- 新增、替换、删除、清空同名条目和校准都只生成待确认提案。正文与卡片展示
  目标、当前值和拟修改值，并明确尚未执行。确认按钮才执行，取消、过期及重复请求
  继续遵守原有权限、时效和幂等规则。
- 日期依据在卡片展示为“模型估算，请核对”“用户提供”或“尚未确定”，不显示 `llm` 等枚举。

## 菜谱、画像与烹饪进度

- 菜谱必须来自检索工具，过敏原由用户画像注入并由检索端过滤，不能被模型省略。
- 单纯推荐请求不提供库存变更工具。已有库存快照时只提供菜谱检索能力，
  只有用户明确要求修改库存、进入已烹饪核对或要求长期记录时才提供相应能力。
- 读取库存后搜索菜谱时保留模型使用目标语言写的推荐，不再用工具结果全集覆盖。
  用户要求一道菜时提示词要求只推荐一道，说明已有食材、缺少的材料和简明做法；
  最终审计同时检查是否提及多道检索结果，附带推荐也算在内，违规进入修复。
  翻译和做法表达由模型完成，不通过模板自动补造菜谱。
- 只读推荐分为检索和回答两个阶段：成功检索后，下一次模型调用不再提供工具，
  改用只生成最终回答的提示词，避免模型在回答阶段继续发起库存操作。
- 原始菜名可与译名并列；来源链接必须存在于检索结果中。空结果不允许编造成推荐。
- 推荐卡片优先显示回答提及的菜谱，其他候选收起；原始候选用于确认菜谱和创建烹饪任务。
- 长期画像变更单独确认；证据记录默认收起。确认菜谱不修改库存，标记已烹饪后
  进入库存核对，实际变更仍需逐条确认。
- 同一请求同时创建变更提案和搜索菜谱时，使用确定性的待确认摘要及来源菜谱信息，
  优先保证没有把提案误述为已执行。

## 回答审计与前端

纯库存和提案回答必须匹配公开摘要，底层完整工具记录仍接受 ID、数量及操作校验。
菜谱回答继续校验检索证据和来源链接。内部 ID、字段名、协议标签及原始时间戳到达
正文时判为可修复违规，沿用一次修复与一次主助手重试上限，失败后返回固定提示。
菜谱参数校验错误返回受控的工具反馈，允许助手在原有递归上限内纠正；错误调用
保留在日志中，不能当作检索成功的证据。没有助手正文时使用固定失败提示，
绝不能回退展示用户消息或结构化输入。模型返回 length 截断结果时直接失败，
重复生成同一片段的回答也不能通过审计，不能以“完成”状态展示半截或循环内容。

回答接口使用公开的 `state` 区分完成、待确认、等待图片校对、失败及拦截；
模型或工具失败的固定提示不再被标为“完成”。
回答接口不再发送 `tool_history` 和内部 `audit_reason`；需要交互的卡片 ID 保留在
结构化字段。执行轨迹仍可展开“诊断信息”查看，默认不展开。
日志保存模型原始输出、工具结果、最终正文及 `public_response`，便于区分模型生成、
后端处理和浏览器展示。历史日志不追补不存在的响应证据。
